# 8.1 Upload 모드 프로그램 구조

Upload 모드 프로그램은 사이버파이에 저장되어 전원이 켜지면 스스로 실행된다(4.3절). PC와 연결되어 있지 않으므로 오류가 발생해도 PC 화면으로 원인을 확인할 수 없다. 따라서 Upload 모드 프로그램은 다음 세 부분을 명확히 구분해 작성하고, 오류가 발생해도 정지하지 않도록 구성한다.

| 부분 | 역할 | 예 |
|---|---|---|
| 초기화 | 전원을 켤 때 한 번 실행 | Wi-Fi 접속, 변수 초기값 설정, 화면 안내 |
| 반복 | 계속 실행하는 본체 | 단추 확인, 주기적 측정·전송 |
| 이벤트 | 특정 입력이 발생했을 때 실행 | 단추 누름, 기기 흔들기 |

## 이벤트 방식

4.4절에서 확인한 대로 mBlock은 이벤트 블록을 데코레이터와 함수로 변환한다. 하나의 프로그램에 이벤트 함수를 여러 개 작성할 수 있다.

```python
import event, time, cyberpi

count = 0

@event.start
def on_start():
    cyberpi.console.println("A: +1  B: reset")

@event.is_press('a')
def on_a():
    global count
    count += 1
    cyberpi.console.println(count)

@event.is_press('b')
def on_b():
    global count
    count = 0
    cyberpi.console.println("reset")
```

`global count`는 함수 안에서 함수 밖의 변수 `count`를 변경하겠다는 선언이다. 이 선언이 없으면 함수 안에서 `count += 1`을 실행할 때 오류가 발생한다.

## 반복 방식

이벤트 방식은 단순한 동작에 편리하지만, 「5초마다 측정」처럼 시간 간격을 관리해야 하는 프로그램에는 반복 방식이 적합하다. 다음은 2026-11-04 정보통신학과 측정 노드 실습의 기기 프로그램 구조를 단순화한 것이다.

```python
import time
import cyberpi

PERIOD = 5                         # 측정 주기(초)
count = 0                          # 측정 횟수(재시작해도 유지)
restarts = 0                       # 오류 재시작 횟수


def measure():
    global count
    count += 1
    bri = cyberpi.get_bri()
    cyberpi.console.clear()
    cyberpi.console.println("n=%d bri=%d" % (count, bri))


def main():
    cyberpi.console.println("start")          # 초기화
    last = time.time()
    while True:                               # 반복
        if cyberpi.controller.is_press("a"):  # 단추 확인
            measure()
            last = time.time()
            time.sleep(0.3)
        if time.time() - last >= PERIOD:      # 주기 측정
            last = time.time()
            measure()
        time.sleep(0.05)


while True:                                   # 오류가 발생해도 정지하지 않도록 감싼다
    try:
        main()
    except Exception as e:
        restarts += 1
        cyberpi.console.clear()
        cyberpi.console.println("ERR " + type(e).__name__)
        time.sleep(3)                         # 3초 뒤 main()부터 다시 실행
```

| 구조 | 설명 |
|---|---|
| `time.time() - last >= PERIOD` | 마지막 측정 시각에서 5초가 지났는지 확인. `time.sleep(5)`로 기다리면 그동안 단추 입력을 확인할 수 없으므로 이 방법을 사용 |
| `time.sleep(0.05)` | 반복을 0.05초마다 실행해 단추 입력을 놓치지 않으면서 처리 부하를 낮춤 |
| `try … except` | `main()`에서 오류가 발생하면 화면에 오류 이름을 표시하고 3초 뒤 다시 실행 |
| 전역 변수 `count` | `main()`이 다시 실행되어도 함수 밖의 값은 유지되므로 측정 횟수가 초기화되지 않음 |

`try` 블록에서 오류(예외)가 발생하면 프로그램을 정지하지 않고 `except` 블록으로 이동해 실행을 계속하는 문법을 예외 처리라고 한다. 측정 노드 실습에서는 약한 신호에서 Wi-Fi 스캔이 실패하거나 특수 문자가 포함된 Wi-Fi 이름 때문에 프로그램이 정지하는 문제가 실제로 발생했고, 이 구조로 해결했다.

## 전원과 포켓쉴드

USB 케이블을 분리하면 사이버파이는 포켓쉴드의 배터리로 동작한다(4.7절). 측정을 시작하기 전에 다음을 확인한다.

1. 포켓쉴드를 사이버파이에 결합하고 전원 스위치를 켠다.
2. USB 케이블을 분리해도 화면과 LED가 동작하는지 확인한다.
3. 수업 중 배터리가 부족하면 USB 케이블로 PC나 충전기에 연결해 충전한다.

## 실습 과제

1. 이벤트 방식 예제에 조이스틱 가운데 누름(`@event.is_press('middle')`)으로 현재 값을 LED 개수로 표시하는 기능을 추가하시오.
2. 반복 방식 예제의 `measure()`에 소리 크기를 추가하고, 주기를 3초로 바꾸시오.
3. `measure()` 안에서 일부러 오류를 발생시키는 코드(`1 / 0`)를 넣고 업로드해, 화면에 오류 이름이 표시된 뒤 다시 실행되는지 확인하시오.

!!! warning "초안 확인 사항"
    반복 방식의 구조(주기 측정, 단추 확인, 예외 재시작)는 2026-11-04 측정 노드 실습의 기기 프로그램에서 동작을 확인했다. 이벤트 방식의 `@event.is_press('b')`, `@event.is_press('middle')` 변환과 이벤트 함수 안의 `global` 사용은 실기기로 확인한 뒤 확정한다.
