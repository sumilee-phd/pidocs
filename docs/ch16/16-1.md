# 16.1 시연 절차

시연 당일에는 여러 팀이 같은 교실과 같은 Wi-Fi를 사용한다. 장비 설치와 연결을 정해진 순서로 진행하면 문제가 발생한 단계를 바로 확인할 수 있고, 시연 시간을 설치에 소비하지 않는다. 등교일의 세부 시간표는 수업 공지에 따른다.

## 등교일 진행 순서

| 순서 | 활동 | 내용 |
|---|---|---|
| 1 | 장비 점검 | 기기 충전 상태, 노트북 전원, 서버 코드와 대체 자료 확인 |
| 2 | 리허설 | 팀별 설치·연결 후 15.3절 시나리오로 1회 연습 |
| 3 | 팀별 시연 | 시연 순서표에 따라 진행 |
| 4 | 점검과 회고 | 16.2절 점검표 작성, 16.3절 회고 |

## 설치·연결 순서

장비는 자료가 흐르는 방향의 역순, 즉 수신하는 쪽부터 준비한다. 서버가 먼저 실행되어 있어야 기기가 처음 전송한 측정값부터 기록된다.

1. 노트북을 전원에 연결하고 교내 Wi-Fi에 접속한다.
2. 명령 창에서 `ipconfig`를 실행해 노트북의 IPv4 주소를 확인한다.
3. 팀 서버를 실행한다(15.1절).

    ```text
    uvicorn main:app --host 0.0.0.0 --port 8620
    ```

4. 명령 창에 「UDP 수신 대기: 8611」이 출력되는지 확인하고, 브라우저에서 `http://127.0.0.1:8620/docs`를 열어 HTTP 수신을 확인한다.
5. 기기 코드의 `SERVER_IP`를 2번에서 확인한 주소로 변경해 Upload 모드로 업로드한다(8.2절).
6. USB 케이블을 분리하고 포켓쉴드 전원으로 기기를 실행한다. 기기 화면에 「WiFi OK」와 IP 주소가 표시되는지 확인한다.
7. 첫 측정값을 전송해 기기 화면의 「send OK」와 서버 명령 창의 「UDP …」 출력을 함께 확인한다.
8. 브라우저에서 `/summary`를 열어 기록이 증가하는지 확인한다.

| 단계 | 확인 표시 | 실패 시 확인 항목 |
|---|---|---|
| 서버 실행 | 「UDP 수신 대기」, `/docs` 화면 | 포트 사용 중 오류, 패키지 설치 |
| 기기 접속 | 「WiFi OK」, IP 주소 | Wi-Fi 이름·비밀번호, 기기 재시작(부록 C) |
| 전송 | 「send OK」, 서버의 「UDP …」 출력 | `SERVER_IP`, `UDP_PORT`, 노트북 방화벽(부록 C) |
| 기록 | `/summary` 건수 증가 | 서버 명령 창의 「UDP 거부」 출력과 원인 |

## 시간 배분

팀당 시연 시간은 다음을 기준으로 한다. 실제 시간은 팀 수와 등교일 시간표에 따라 조정한다.

| 구분 | 시간 | 내용 |
|---|---|---|
| 설치·연결 | 3분 | 위 순서 5~8번(서버는 앞 팀 시연 중에 미리 실행) |
| 시연·발표 | 10분 | 15.3절 시연 흐름 |
| 정리 | 2분 | 장비 철수, 다음 팀 설치 |

설치·연결이 3분 안에 끝나지 않으면 15.3절의 장애 대비안으로 전환한다. 예를 들어 「send FAIL」이 계속 표시되면 원인을 찾는 데 시간을 소비하지 않고, USB를 연결한 Live 모드 시연과 미리 저장한 기록의 재생 시험(14.4절)으로 진행한다. 원인 확인은 시연이 끝난 뒤 회고에서 진행한다.

## 시연 진행 원칙

| 원칙 | 내용 |
|---|---|
| 시나리오 준수 | 15.3절 시연 흐름과 조작 순서를 그대로 따른다 |
| 화면 공유 | 기기 표시와 서버 화면을 청중이 함께 볼 수 있게 배치한다 |
| 수치 근거 제시 | 판정 기준과 정확도는 수치로 설명한다(7·11장) |
| 한계 설명 | 재현 측정의 조건, 예시 자료 사용 여부, 확인하지 못한 부분을 함께 설명한다 |
| 비밀 값 비공개 | 화면에 API 키, Wi-Fi 비밀번호가 표시되지 않도록 한다 |

## 확인 문제

1. 본인 팀의 설치·연결 순서를 위 8단계에 맞춰 작성하고, 각 단계에서 확인할 표시를 적으시오.
2. 설치·연결이 3분을 초과했을 때 전환할 대체 시연 방법을 15.3절 장애 대비안에서 고르시오.
3. 서버를 기기보다 먼저 실행해야 하는 이유를 설명하시오.
