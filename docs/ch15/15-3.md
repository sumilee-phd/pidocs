# 15.3 시연 시나리오 작성

16주차 시연은 팀당 정해진 시간 안에 진행한다. 시연 시나리오는 무엇을 어떤 순서로 보여 줄지, 누가 무엇을 조작할지, 장애가 발생하면 어떻게 대응할지를 미리 정한 문서다. 시나리오가 없으면 설치와 연결에 시간을 소비해 핵심 기능을 보여 주지 못하는 경우가 많다.

## 시연 흐름

다음은 시연 시간 10분 기준의 예시다(16.1절의 시간 배분에 맞춘다).

| 시간 | 단계 | 내용 | 담당 |
|---|---|---|---|
| 0:00~1:00 | 문제 소개 | 현장 문제와 측정 대상(12.4절 양식) | 발표 |
| 1:00~2:00 | 시스템 구성 | 15.1절 구성 요소 표 | 발표 |
| 2:00~5:00 | 실시간 시연 | 센서 조작 → 기기 표시 → 서버 기록 갱신 | 기기·서버 |
| 5:00~6:30 | 판정 근거 | 임계값 분위수 또는 모델 평가 결과(정확도·교차 평가) | 분석 |
| 6:30~8:00 | 보고 | AI 보고 문장과 수치 검증 결과 | 서버·보고 |
| 8:00~10:00 | 질의응답 | | 전원 |

실시간 시연(2:00~5:00)에서 보여 줄 조작은 3가지 이내로 정한다. 예를 들어 소음 신호등이라면 「조용한 상태 → 대화 → 손뼉」처럼 단계가 바뀌는 조작을 순서대로 수행하고, 각 조작에서 기대하는 화면을 미리 적어 둔다.

## 장애 대비안

시연 장소의 네트워크와 기기 상태는 연습 때와 다를 수 있다. 장애마다 대체 시연 방법을 정해 둔다.

| 장애 | 증상 | 대체 시연 방법 |
|---|---|---|
| 교내 Wi-Fi 불통 | 기기 화면 「WiFi FAIL」 | USB로 연결해 Live 모드로 측정·판정·표시 시연(4.3절) |
| 서버 응답 없음 | 기기 화면 「send FAIL」 | 미리 저장한 기록으로 14.4절 재생 시험 시연 |
| AI API 불통·키 오류 | 보고 문장 생성 실패 | 13.4절 대체 보고(요약 표)와 이전에 생성·검증한 문장 제시 |
| 배터리 부족 | 기기 꺼짐 | USB 전원 연결, 예비 기기 |
| 센서 값 이상 | 범위 밖 값, 변화 없음 | 기기 재시작, 15.2절 입력 검증 결과 설명 |

대체 시연에 필요한 자료(기록 CSV, 생성·검증한 보고 문장, 화면 캡처)는 시연 전날까지 노트북에 저장해 둔다. 인터넷이 없어도 열 수 있어야 한다.

## 시나리오 점검

시나리오를 작성한 뒤 팀원끼리 실제 시간을 재면서 한 번 이상 연습한다. 다음 질문에 모두 「예」로 답할 수 있으면 준비가 끝난 것이다.

1. 설치·연결을 제외한 시연이 정해진 시간 안에 끝나는가?
2. 각 단계의 담당자가 자기 조작과 대사를 알고 있는가?
3. 장애 대비안의 대체 자료가 노트북에 저장되어 있는가?
4. 판정 근거(임계값·정확도)를 수치로 설명할 수 있는가?
5. AI 보고 문장의 수치가 검증을 통과했는가?

## 확인 문제

1. 본인 팀의 시연 흐름 표를 작성하고, 연습에서 실제로 걸린 시간을 함께 기록하시오.
2. 본인 팀 시스템에서 발생 가능성이 가장 높은 장애 두 가지를 정하고 대체 시연 방법을 구체적으로 작성하시오.
3. 시연 중 질문을 받을 가능성이 높은 내용 세 가지와 답변을 준비하시오.
