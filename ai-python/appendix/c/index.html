    C. 문제 해결¶

    실습 중 자주 발생하는 문제와 확인 순서를 정리한다. 문제가 발생하면 표의 위쪽 항목부터 차례로 확인한다. 확인 순서대로 점검해도 해결되지 않으면 증상, 화면의 오류 메시지, 이미 확인한 항목을 함께 교수자에게 알린다(1.5절의 질문 작성 형식).

    기기 연결¶

    증상 확인 순서 관련 절
    mBlock이 사이버파이를 인식하지 못함 ① 사이버파이 전원 ② USB 케이블 교체(충전 전용 케이블은 데이터를 전송하지 못함) ③ PC의 다른 USB 포트 ④ mBlock 장치 드라이버 설치 ⑤ 연결 창의 포트 선택 4.2
    연결이 자주 끊김 ① USB 허브 대신 PC에 직접 연결 ② 케이블 교체 ③ 다른 프로그램(다른 mBlock 창)의 포트 사용 여부 4.2
    USB를 분리하면 기기가 꺼짐 ① 포켓쉴드 결합 ② 포켓쉴드 전원 스위치 ③ 배터리 충전 4.7, 8.1
    USB를 분리하면 프로그램이 멈춤 Live 모드 프로그램은 PC에서 실행되므로 USB를 분리하면 멈춘다. 기기 단독 실행은 Upload 모드로 업로드 4.3

    펌웨어¶

    증상 대응 관련 절
    연결할 때 펌웨어 업데이트 창이 표시됨 진행하기 전에 교수자에게 알린다. 실습 기기의 펌웨어를 같은 버전으로 유지해야 같은 코드가 같게 동작한다 4.2
    업데이트 중 연결이 끊김 기기를 그대로 두고 교수자에게 알린다. 임의로 재시도하지 않는다 4.2
    업데이트 후 동작 확인 4.4절의 LED 깜빡임 프로그램을 실행 4.4

    기기 프로그램¶

    증상 확인 순서 관련 절
    업로드 후 아무 반응이 없음 ① 업로드 완료 표시 ② 전원을 껐다 켜서 @event.start 함수 실행 ③ 들여쓰기 오류 4.4, 8.1
    화면에 「ERR …」이 표시됨 8.1절 반복 방식의 예외 처리가 표시한 오류 이름이다. 오류 이름으로 원인을 찾는다(예: NameError는 정의하지 않은 이름 사용) 8.1
    센서값이 변하지 않음 ① Live·Upload 모드와 코드의 일치 ② 측정 주기(time.sleep) ③ 기기 재시작 4.6
    LED 스트립이 점등되지 않음 ① 포켓쉴드 전원 ② 케이블을 연결한 포트(S1·S2)와 코드의 port 값 ③ 밝기 설정(led_set_bri) 4.7

    Wi-Fi와 전송¶

    증상 확인 순서 관련 절
    「WiFi FAIL」 ① Wi-Fi 이름·비밀번호의 오타와 대소문자 ② 공유기와의 거리(약한 신호에서는 접속·스캔이 실패할 수 있음) ③ 기기 재시작 8.1, 8.2
    특수 문자가 포함된 Wi-Fi 이름에서 프로그램이 정지 측정 노드 실습에서 실제로 발생한 문제다. 예외 처리 구조(8.1절)로 정지를 방지하고, 교수자가 안내한 Wi-Fi를 사용 8.1
    「send FAIL」 ① 서버 실행 여부 ② SERVER_IP가 서버 PC의 현재 IP 주소인지(ipconfig) ③ UDP_PORT가 서버의 수신 포트와 같은지 ④ 기기와 서버 PC가 같은 Wi-Fi에 연결되어 있는지 ⑤ 서버 PC의 방화벽 8.2, 15.1
    서버 명령 창에 「UDP 거부」 출력된 오류 이름을 확인한다. ValidationError는 지점·값 범위 등 형식 오류, JSONDecodeError는 JSON 문자열 구성 오류 15.1

    Windows 방화벽

    서버를 처음 실행하면 Windows 방화벽이 Python의 네트워크 접근을 허용할지 묻는 창을 표시할 수 있다. 허용하지 않으면 같은 PC 안의 시험(fake_node.py)은 성공해도 기기의 데이터그램은 수신되지 않는다. 학교·회사 노트북은 방화벽 설정에 관리자 권한이 필요할 수 있으므로, 이 경우 실습실 PC를 사용한다.

    Colab¶

    증상 원인과 대응 관련 절
    FileNotFoundError 자료 파일이 없다. 노트북 첫 셀의 자료 내려받기 명령을 실행 1.3
    NameError 앞 셀에서 정의한 이름을 아직 실행하지 않았다. 「런타임 → 이전 셀 실행」 또는 「모두 실행」 1.3
    ModuleNotFoundError 패키지가 설치되어 있지 않다. 14.2절처럼 pip install로 설치 14.2
    한동안 사용하지 않은 뒤 변수가 모두 사라짐 런타임 연결이 끊겨 초기화되었다. 위에서부터 다시 실행 1.3
    새 노트북을 열 수 없다는 세션 수 안내 「런타임 → 세션 관리」에서 사용하지 않는 세션을 종료 1.3

    서버¶

    증상 원인과 대응 관련 절
    422 응답 요청 자료가 Measure 모델의 형식과 다르다. 응답의 detail에서 거부 이유를 확인 14.2
    서버 실행 시 포트 사용 중 오류 같은 포트로 실행 중인 다른 서버가 있다. 이전 명령 창의 서버를 Ctrl+C로 종료하거나 --port를 변경 14.2
    서버를 다시 실행하면 기록이 사라짐 이 책의 서버는 기록을 메모리의 리스트에 저장한다. 시연 기록은 CSV 등으로 별도 저장 14.2

    Gemini API¶

    증상 원인과 대응 관련 절
    API 키가 없다는 안내 출력 Colab 보안 비밀에 GEMINI_API_KEY가 등록되지 않았거나 노트북 접근이 허용되지 않았다 13.1
    API 키가 유효하지 않다는 오류 키를 잘못 입력했거나 삭제된 키다. Google AI Studio에서 키를 확인 13.1
    사용량 한도 초과 오류(429) 짧은 시간에 요청을 많이 보냈다. 잠시 후 다시 실행하고, 반복 호출에는 재시도 횟수를 제한 13.4, 15.2
    응답 문장의 수치가 요약값과 다름 생성형 AI의 출력은 매번 달라질 수 있다. check_report로 검증하고 실패하면 대체 보고 사용 13.4
